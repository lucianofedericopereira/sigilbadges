      Marker syntaxSintaxis del marcadorSintassi del marcatore

      A single badge, or a responsive row of badges sharing one set of defaults. Both idioms keep their spec in the marker's own tag rather than the disposable body, so a re-run never loses it.Una sola insignia, o una fila responsiva de insignias que comparten un mismo conjunto de valores predeterminados. Ambos modelos guardan su especificación en la propia etiqueta del marcador en lugar del cuerpo desechable, así que una reejecución nunca la pierde.Un singolo badge, oppure una riga responsive di badge che condividono un unico insieme di valori predefiniti. Entrambi gli idiomi mantengono la propria specifica nel tag stesso del marcatore anziché nel corpo usa e getta, così una riesecuzione non la perde mai.

      The badge-row: key=value ... header is optional and sets defaults every line inherits/overrides. The body between the markers is pure rendered output, fully regenerated on every run — never hand-edit it.El encabezado badge-row: key=value ... es opcional y define valores predeterminados que cada línea hereda o sobrescribe. El cuerpo entre los marcadores es salida puramente renderizada, totalmente regenerada en cada ejecución — nunca lo edites a mano.L'intestazione badge-row: key=value ... è opzionale e imposta valori predefiniti che ogni riga eredita o sovrascrive. Il corpo tra i marcatori è output puramente renderizzato, rigenerato completamente a ogni esecuzione — non modificarlo mai a mano.

      Real markers have no space after <!-- or before -->. The scanner matches anywhere in the file, including inside fenced code blocks — it has no notion of Markdown fences.Los marcadores reales no tienen espacio después de <!-- ni antes de -->. El escáner encuentra coincidencias en cualquier parte del archivo, incluso dentro de bloques de código cercados — no tiene noción de los fences de Markdown.I marcatori reali non hanno spazio dopo <!-- né prima di -->. Lo scanner trova corrispondenze in qualsiasi punto del file, anche all'interno di blocchi di codice recintati — non ha alcuna nozione dei fence di Markdown.

      The workflow in .github/workflows/ci.yml runs the test suite unmodified across a matrix of Perl releases (native runner + older interpreters), and a dogfooding job that runs the action against this repo's own README.md with --check — the same pattern the badges below in the changelog are generated with.El workflow en .github/workflows/ci.yml ejecuta la suite de pruebas sin modificar en una matriz de versiones de Perl (runner nativo + intérpretes más antiguos), y un job de dogfooding que ejecuta la action contra el propio README.md de este repo con --check — el mismo patrón con el que se generan las insignias del registro de cambios más abajo.Il workflow in .github/workflows/ci.yml esegue la suite di test senza modifiche su una matrice di versioni di Perl (runner nativo + interpreti più vecchi), e un job di dogfooding che esegue l'action sul README.md di questo stesso repo con --check — lo stesso schema con cui vengono generati i badge nel changelog qui sotto.
