    Documentation

    sigilbadges

    Generated SVG badges (logo + text), spliced into your README via marker comments. No template language, no CPAN dependencies, one Perl script.

    View on GitHub Changelog

    Grammar

    Marker syntax

    A single badge, or a responsive row of badges sharing one set of defaults. Both idioms keep their spec in the marker's own tag rather than the disposable body, so a re-run never loses it.

    A single badge

    <!--[[ badge: logo=php label="PHP" message="8.5" ]]-->...<!--/-->

    A row of badges

    <!--[[ badge-row: style=chip
logo=php label="PHP" message="8.5"
logo=node message="20.x"
]]-->...<!--/-->

    The badge-row: key=value ... header is optional and sets defaults every line inherits/overrides. The body between the markers is pure rendered output, fully regenerated on every run — never hand-edit it.

    Real markers have no space after <!-- or before -->. The scanner matches anywhere in the file, including inside fenced code blocks — it has no notion of Markdown fences.

    Keys

    keymeaningdefault
    logoname of an SVG in assets/logos/ (no extension)—
    labelleft-hand text—
    messageright-hand text—
    colorbare hex, no # (e.g. color=336791)logo's brand color, else 555555
    label-colorbare hex for the label segment555555
    logo-colorbare hex to recolor the logoFFFFFF
    stylechip, flat, flat-square, plastic, for-the-badgechip
    idexplicit filename stem (assets/badges/<id>.svg)derived from logo / label / message
    linkwraps the badge <img> in an <a href="...">—
    altalt text on the <img>label + message, else logo

    Colors are always a bare 6-digit hex value — no CSS color names, no leading #.

    Reference

    Styles

    Five renderers, one grammar. flat, flat-square, and plastic only render as two colored segments when both label and message are given (shields.io's own convention) — with just one of the two, it collapses to a single segment in color.

    chiprounded chip, top-to-bottom gradient, logo first — this project's own look
    flattwo-tone rectangle, rounded corners — the classic shields.io look
    flat-squaresame two-tone layout as flat, sharp corners
    plasticsame two-tone layout, with a glossy highlight band
    for-the-badgebigger, bold, uppercase label/message text

    Usage

    Command line

    perl sigilbadges.pl [--file README.md] [--badges-dir assets/badges] [--check]
    flagmeaningdefault
    --filethe Markdown file to scan and rewriteREADME.md
    --badges-dirwhere generated .svg files are writtenassets/badges
    --checkexit non-zero if the file or any badge is out of date, without writing anythingoff — CI-friendly

    GitHub Marketplace

    GitHub Action

    The same script, wrapped as a composite action — no interpreter setup step, since GitHub-hosted runners ship Perl natively.

    - uses: lucianofedericopereira/sigilbadges@v0.1.0
  with:
    file: README.md
    badges-dir: assets/badges
    check: "false"
    commit: "true"
    inputmeaningdefault
    fileMarkdown file to scan and rewriteREADME.md
    badges-dirwhere generated SVGs are writtenassets/badges
    checkfail the job instead of writing, when out of datefalse
    commitcommit and push changes back to the branchtrue
    commit-messagecommit message used when commit is truedocs: update badges [skip ci]

    Marketplace branding uses the award icon on a gray-dark background — the same graphite tone as the sigilbadges.svg wordmark, not the green GitHub defaults to for most starter actions.

    Continuous Integration

    CI

    The workflow in .github/workflows/ci.yml runs the test suite unmodified across a matrix of Perl releases (native runner + older interpreters), and a dogfooding job that runs the action against this repo's own README.md with --check — the same pattern the badges below in the changelog are generated with.

    prove -r t
